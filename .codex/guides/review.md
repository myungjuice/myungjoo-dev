# 리뷰 가이드

## 역할 구분

- **CodeRabbit**은 외부 보조 의견을 제공한다. 제안을 그대로 적용하지 않고 저장소 맥락,
  기술적 정확성, 회귀 위험을 검증해 선택적으로 수용한다.
- **Code Reviewer**는 구현자와 독립된 필수 검토자다. 요청한 동작, 기존 패턴, 타입
  안전성, i18n, 접근성, 테스트 공백과 회귀 가능성을 최종 diff에서 확인한다.
- **QA Engineer**는 승인된 완료 조건과 실제 사용자 동작의 증거를 수집한다. `standard`와
  `high-risk`에서는 구현자와 다른 agent가 수행한다.

문서·GitHub 준비처럼 프로덕션 코드가 없는 작업은 기술 사실이나 공개 변경 검토가 필요할
때 Code Reviewer를 추가한다. 역할별 결과는 오케스트레이션 skill의 handoff 형식을 따른다.

## CodeRabbit 리뷰 polling

- PR 생성 후 polling 실행 여부를 권장안, 근거, 예상 대기·알림 영향과 함께 사용자에게
  번호 선택지로 질문한다.
- 사용자가 승인한 경우에만 백그라운드 polling을 시작한다.
- polling하지 않아도 사용자가 공유한 CodeRabbit 피드백은 동일한 절차로 처리한다.

## 리뷰 대응 절차

1. 리뷰 내용을 정확성, 회귀 위험, 테스트, i18n, 접근성, 스타일로 분류한다.
2. 각 항목의 수용 여부와 근거를 요약한다.
3. 수정이 필요한 항목은 변경안과 검증 명령을 먼저 제시한다.
4. 사용자 승인 후에만 수정한다.
5. review fix마다 관련 테스트와 정적 검사를 다시 실행하고, 누적 변경의 최종
   `pnpm verify` 결과를 보고한다.
6. 사용자 승인 전에는 Draft PR을 Ready로 바꾸거나 병합하지 않는다.
7. auto-merge를 설정하지 않으며 병합은 별도 승인 후에만 수행한다.

## 독립 리뷰와 QA 증거

- 구현자는 자신의 두 번째 검토를 독립 리뷰나 독립 QA로 세지 않는다.
- Code Reviewer는 diff의 발견 사항을 심각도와 근거 위치 순으로 제시하고, 발견 사항이
  없더라도 검증 공백과 남은 위험을 분리해 보고한다.
- QA Engineer는 실행 환경, 사용자 시나리오, 기대·관찰 결과와 실패를 재현할 정보를
  기록한다.
- 수정 뒤에는 영향받은 QA 시나리오와 리뷰 발견 사항의 관련 검증을 다시 수행한다.
